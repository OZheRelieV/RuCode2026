# Анти-фейк

## Описание задачи

Мошенники всё чаще используют синтезированную и сконвертированную речь: звонят «голосом родственника», обходят голосовую биометрию, генерируют массовые обзвоны нейросетевыми голосами. Оператор связи стоит на первой линии этой атаки: нужно уметь отличать естественную речь от подделки прямо в звонке.

Участнику предлагается роль инженера антифрод-платформы: построить модель, которая по аудиозаписи определяет, произнесена ли фраза человеком или сгенерирована/подделана машиной (TTS, voice conversion). Тема голосовых дипфейков — одна из самых горячих в индустрии, и для МТС эта задача является продуктовым кейсом защиты абонентов.

## Задание

**Ваша задача** — по аудио определить, является ли голос синтезированным. Обратите внимание: в тестовом наборе голос синтезируется иначе, чем в тренировочном.

**Вход**: аудиозапись с короткой репликой.  
**Выход**: вещественная оценка от 0 до 1 — уверенность модели в том, что запись поддельная (spoof) или настоящая (bona fide).

**Метрика: ROC‑AUC.**

## Исследование

Логика решения строилась следующим образом:

1. анализ баланса целевой переменной;
|target|spoof|bonafide|
|-|-|-|
|proportion|0.898345|0.101655|

> **Вывод**
>
> Cильный дисбаланс в пользву сгенерированный аудио.  
> Нужна сильная валидация, которая строится следующим образом:
>
> - одна группа спикеров и одни типы атак на обучении;
> - проверяем на других типах атак и другой группе спикеров.
>
> Это позволит понять, насколько модель, действительно, улавливает признаки сгенерированной записи.

2. анализ распределения длительностей записей;

|train|public test|
|-|-|
|распределение с правой асимметрией и длинным хвостом (похоже на лог нормальное)|дискретное распределение|

> **Вывод**
>
> Длительности записей из публичного тестового набора сосредоточены около нескольких значений: 2, 3, 3.5, 4 и 4.5 секунды. Тренировочный набора имеет более широкий диапазон длительностей и длинный правый хвост, однако его медиана ниже: 3.20 секунды против 4.00 секунды у данных их публичного тестового набора.
>
> Эту информацию, предполагалось, использовать, например, для объединения в одних батч по длительности, а также использовать часть длительностей (от 1.5 сек. до 4.5 сек с  шагом 0.5 сек) для валидации. Однако, она не вошла в итоговое решение.

3. построение базового решения на основе catboost с генерацией CQT признаков.

> **Вывод**
>
> CQT выбран как альтернативное спектральное представление с логарифмической частотной сеткой и зависящим от частоты временным разрешением. Проверялась гипотеза, что эти свойства помогут выделить артефакты синтеза.
>
> Получилась слишком оптимистическая оценка roc_auc (**0.8-0.9**) на StratifiedKFold(n_splits=5).

4. adversarial check;

> **Вывод**
>
> roc-auc показал 1.0. Схема валидации: StratifiedKFold(n_splits=5). Набор данных: cqt признаки.  
> В свою очередь, это указывает на различия между наборами в используемом пространстве признаков.

5. использование нейронных сетей в zero-shot режиме

|модель|roc_auc|
|-|-|
|lab260/AASIST3|83.12|
|lab260/Spectra-AASIST|99.66|

> **Вывод**
>
> zero-shot режим показал успешность применения моделей от lab260.  
> Прогон `lab260/Spectra-AASIST` на тренировочном наборе показал бимодальное распределение с хорошим разделением между классами.
>
> Было принято решение: **использовать дальше lab260/Spectra-AASIST в zero-shot режиме**.

6. поиск способов предобратки

**roc_auc_lb (baseline)** = 99.66

|id|exp|lb|
|-|-|-|
|1|tile instead of pad|99.53|
|2|preemphasis(coeff=0.97)|99.59|
|3|windows|99.67|
|4|3-position zero-padding + 3-crop averaging|99.7|
|5|preemphasis + tile|98.56|
|6|5-position zero-padding + 5-crop averaging|99.71|

> **Вывод**
>
> Были рассмотрены такие методы предобратки сигнала:
>
> - дополнение сигнала до нужной длины не нулями, а засчёт повторения сигнала (не дало прироста);
> - использовать фильтр, который подавляет низкие частоты относительно высоких, подчёркивая быстрые изменения аудиосигнала (не дало прироста);
> - нарезать сигнал на окна фиксированной длины, а затем инферить модели и полученные оценки разности логитов усреднять (**+0.01 п.п.**);
> - усреднять предсказания по трем положениям короткой записи внутри нулевого окна, а для длинных — по трем фрагментам. (**+0.04 п.п.**);
> - комбинация фильтра и паддинга повторением сигнала (не дало прироста);
> - усреднять предсказания по пяти положениям короткой записи внутри нулевого окна, а для длинных — по пяти фрагментам. (**+0.05 п.п.**);
>
> В итоге была выбрана конфигурация, которая дала **+0.05 п.п** к roc_auc_lb (baseline) - усреднять разности логитов по пяти положениям короткого сигнала внутри окна с нулевым дополнением либо по пяти фрагментам длинной записи.

7. дообучение `lab260/Spectra-AASIST`

> **Вывод**
>
> При замороженном энкодере Wav2Vec2 дообучались блоки `bridge + aasist`. Проверены learning rate 1e-5 и 3e-6. В обоих случаях roc_auc на отложенных атаках A05/A06 снизился относительно исходной модели, поэтому были сохранены исходные веса.
>
> Было принято решение: **оставить исходные веса и работать с ними**.

8. тестирование `lab260/Spectra-AASIST3` в zero-shot

> **Вывод**
>
> Конфигурация предобработки была зафиксирована как прошлом шаге (5-position zero-padding + 5-crop averaging) и изменений не получила.  
> Модель показала **100** на лидерборде на публичном наборе данных.
>
> Комбинация `lab260/Spectra-AASIST3` + `5-position zero-padding + 5-crop averaging` была выбрана в качестве итоговой.

## Запуск

1. Склонировать [репозиторий](https://github.com/OZheRelieV/RuCode2026):
> git clone --branch c_task --single-branch https://github.com/OZheRelieV/RuCode2026.git c_task

2. Перейти в папку
> cd c_task

3. Скачать данные: [Ссылка на данные](https://drive.google.com/drive/folders/1RXBJiYEHBT3U9gOuzhguT5y8ytOjHrEx?usp=sharing)

    3.1 Скачать приватный тестовый набор: [Ссылка на данные](https://drive.google.com/drive/folders/1RXBJiYEHBT3U9gOuzhguT5y8ytOjHrEx)

5. Данные распаковать и положить внутрь папки `c_task`
- тренировочные данные в `train/`
- публичный тестовый набор в `public_test`
- приватный тестовый набор в `private_test`

5. **Для дальнейшей работы нужен uv**. Создать виртуальное окружение
> uv sync

6. Активировать виртуальное окружение
> source .venv/bin/activate

7. Запустить решение

     7.1 Инференс на публичном тестовом наборе
     > python main.py --test public_test

    7.2 Инференс на приватном тестовом наборе
    > python main.py --test private_test

> **В команде запуска обязательно выбрать один из вариантов public_test/private_test**

8. В папке `subs/` будет файл `submission.csv`
